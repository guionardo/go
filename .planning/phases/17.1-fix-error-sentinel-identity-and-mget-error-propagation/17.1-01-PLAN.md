<objective>
Close W1 (sentinel identity and double prefix) and W2 (MGet's error surface) in `cache/sqlite`, and make the cache-level sentinel documentation tell the truth.

Purpose: `cache.ErrClosed` is advertised as *the* closed sentinel, yet `errors.Is(err, cache.ErrClosed)` is false for the sqlite provider and every closed error carries the `cache/sqlite:` token twice. `MGet` silently swallows the deferred open error at `Warn` while the docs claim every database-needing operation returns it. Both are consumer-visible contract defects found by the v1.8 milestone audit; the fix is three code sites (`ErrClosed`, `check()`, one log call) plus four doc sites.

Output: a single-prefix, dual-sentinel error contract proven by exact-string assertions; `MGet` documented as the deliberate exception and loud when the cache is broken; `cache/doc.go` and `cache/errors.go` describing the sentinel set that actually exists.
</objective>

- `cache/sqlite/sqlite.go` (MOD) — `ErrClosed` becomes a wrapped sentinel; `check()` becomes wrap-once; the `New` doc comment names `MGet` as the exception.
- `cache/sqlite/sqlite_test.go` (MOD) — new const `closedMessage`; strengthened `TestClosedErrorPrefix`, `TestClosedOps`, `TestOptimizableClosed`; new `TestDeferredErrorPrefix` (subtests `invalid_path_prefixed_once`, `bare_open_error_wrapped_once`).
