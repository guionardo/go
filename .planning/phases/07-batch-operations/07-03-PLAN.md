## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user code → redis/valkey provider | User-provided K,V pairs serialized and sent over network via pipeline |
| pipeline execution → command results | Pipeline Exec returns aggregate error; individual commands may have succeeded/failed independently |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06 | Denial of Service | Pipeline with large batch | low | accept | go-redis Pipeline and valkey-go DoMulti batch commands in one TCP round trip. Connection pool exhaustion is possible with very large batches but callers are responsible for batch sizing. Same pool config as single-key ops. |
| T-07-07 | Tampering | Pipeline partial failure masking | low | accept | MGetFunc checks EACH individual command result after pipe.Exec() (Pitfall 3). Pipeline-level errors do NOT mask per-command success/failure. MSet/MDel use pipeline-level error which correctly represents batch atomicity. |
| T-07-08 | Spoofing | valkey initErr guard | low | accept | initErr guard prevents batch ops on uninitialized clients — same protection as single-key ops. No new bypass path. |
</threat_model>
