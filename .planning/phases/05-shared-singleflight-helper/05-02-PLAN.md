<objective>
Implement the `DoChan` cancel-aware variant of `cache.SingleflightGetOrSet[K, V]` (D-12) and the `cache.ErrCanceled` sentinel (D-09/D-10), validated by tests for prompt waiter abandonment (SF-06), value-if-ready semantics (D-08), and leader-path error identity (D-11).

Purpose: HTTP-facing GetOrSet callers must release at cancel latency instead of blocking for the setter's full duration (validated in spike 008: ~15 ms vs ~300 ms). DoChan registers the caller on the group and selects between its own ctx and the result channel; a canceled waiter abandons its own wait while the leader's computation continues untouched.

Output: `cache/singleflight.go` (+`DoChan`), `cache/errors.go` (+`ErrCanceled`), `cache/singleflight_test.go` (+DoChan tests), `cache/cache_test.go` (+`err_canceled` sentinel subtest), `cache/example_test.go` (+`ExampleSingleflightGetOrSet_DoChan`).   <behavior>
    Testable contract (RED phase writes these; ALL MUST fail before implementation exists):

    - Case 1 — canceled waiter returns ErrCanceled: a blocked setter (channel-gated) is the leader; a waiter calls DoChan with a cancelable ctx; cancel the waiter's ctx → the waiter returns an error promptly while the leader is still computing; assert errors.Is(err, cache.ErrCanceled) AND errors.Is(err, context.Canceled) both hold (D-10); release the setter; the leader still completes, stores the value, and a subsequent Get hits it (D-04 — waiter cancellation never cancels the shared work).
    - Case 2 — value-if-ready wins (D-08): the leader finishes and stores BEFORE the waiter's ctx is canceled; then cancel the waiter's ctx → DoChan returns the value, NOT ErrCanceled (non-blocking result select precedes ctx.Done()); assert the returned value equals the leader's.
    - Case 3 — shared value / setter-once: N concurrent DoChan callers on the same key → setter runs exactly once, all callers receive the identical value.
    - Case 4 — setter error shared with waiters: leader's setter returns an error → a DoChan waiter receives that exact error (spike 003 — same error object identity via errors.Is on a sentinel setter error).
    - Case 5 — sentinel identity: cache.ErrCanceled.Error() contains "canceled"; the err_canceled subtest inside TestCacheSentinelErrors (cache/cache_test.go) passes.
    - Case 6 — leader cancel (D-04/D-11): a DoChan caller IS the leader — its setter signals start via a channel (proving the fn and the leader signal have started), then blocks on <-ctx.Done(); canceling the LEADER's own ctx → DoChan returns the raw ctx.Err(): errors.Is(err, context.Canceled) holds AND errors.Is(err, cache.ErrCanceled) does NOT hold (the leader path never wraps — D-11; the leader's cancellation is the setter's ctx, so the fn completes with ctx.Err() and the result channel wins — D-04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| waiter → DoChan select | A canceled waiter's ctx event races the shared result channel; the value-if-ready rule (D-08) decides the outcome |
| waiter → leader computation | Waiter contexts must never reach or cancel the shared setter (D-04) |
| DoChan result channel → caller | The singleflight.Result channel must never leak past the method boundary (D-12) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | DoS | DoChan waiter select | high | mitigate | A canceled waiter must abandon its own wait promptly (SF-06): select on ctx.Done() so the goroutine releases at cancel latency instead of blocking for the setter; verify with TestSingleflightGetOrSet_DoChan_CanceledWaiter measuring prompt return (~15 ms validated in spike 008) |
| T-05-07 | Spoofing | ErrCanceled / error identity | medium | mitigate | ErrCanceled wraps the waiter's ctx.Err() with two %w verbs so errors.Is matches BOTH cache.ErrCanceled and context.Canceled (D-10); test asserts both — a wrapping bug breaks caller error handling |
| T-05-08 | DoS | shared computation | medium | mitigate | A waiter cancel must not cancel/abort the leader (D-04): only the waiter's own select is gated by its ctx; the leader's fn completes and Set lands — asserted in the canceled-waiter test's post-release store check |
| T-05-09 | Information Disclosure | Result channel | low | mitigate | DoChan never returns or exposes the singleflight.Result channel (D-12) — callers only see (V, error); no channel internals in the public API |
| T-05-13 | DoS | DoChan leader path | high | mitigate | The unordered ctx.Done()/result select could wrap the leader's own cancellation in ErrCanceled — instead the ctx.Done() case re-reads ch non-blocking then consults the leader signal (leaderCh closed by the fn); a leader blocks on ch and returns the raw setter ctx.Err() (D-04/D-11); verify with TestSingleflightGetOrSet_DoChan_LeaderCancel asserting errors.Is(err, context.Canceled) && !errors.Is(err, cache.ErrCanceled) |
| T-05-SC | Tampering | module deps | low | accept | No new packages this plan; golang.org/x/sync v0.22.0 already pinned (D-15) — no package-legitimacy checkpoint required |
</threat_model>
