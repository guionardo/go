<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| benchmark -> filesystem | `sqlite/File` and `BenchmarkPrimitives/sqlite/File` create real databases; a fixed or user-cache path would write outside the workspace |
| benchmark -> test process lifetime | SQLite handles must be closed before `b.TempDir()` removal, or Windows fails the run with a sharing violation |
| benchmark -> measured signal | An unbounded key space turns a measurement into a growing-database measurement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-05 | Tampering (local) | file-mode benchmark paths in `cache/bench_test.go` | medium | mitigate | Every path is derived from `b.TempDir()` with a fixed basename (`batch.db`, `primitives.db`); no absolute path, no `sqlite.WithName`, no user cache directory |
| T-17-06 | Denial of service (CI flake) | SQLite handle / sidecar leak on the windows leg | medium | mitigate | `b.Cleanup(Close)` registered after `b.TempDir()` so it runs first (LIFO); verified locally on darwin and exercised by the windows CI leg |
| T-17-07 | Denial of service | unbounded database growth during a timed loop | low | mitigate | `primitiveKeyRing = 1024` bounds the key space; `batchSizes` stays 1/10/100/1000; `make benchmark-quick` (~20 s) is the validation target, and RESEARCH Pitfall 8 records the ~5 min cost of the full `make benchmark` so it is not mistaken for a hang |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs this phase (`go.mod` untouched, no new module); the reserved row stands for any future induced install |
