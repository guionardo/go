## Tech Debt (5 warnings, 0 blockers)

**W1 — error sentinel identity + double prefix** (`PROV-04`, `QUAL-03`). `sqlite.ErrClosed`/`ErrInvalidPath` embed the `cache/sqlite:` prefix and `check()` wraps them again → `cache/sqlite: cache/sqlite: cache is closed`. Separately `errors.Is(err, cache.ErrClosed)` is false for sqlite, though `cache/errors.go:43` advertises that sentinel; no provider returns `cache.ErrClosed` (pre-existing repo-wide). The existing test only asserts the substring, which is why the duplication escaped.

**W2 — `MGet` swallows the deferred open error** (`BATCH-01`, `QUAL-03`). With a bad path, `Get`/`Set`/`MSet`/`MDel` return `invalid path` but `MGet` returns an empty map (`batch.go:77-81`). `doc.go:60-61`'s unqualified "returned by the first operation that needs the database" is false for `MGet`.

**W3 — sqlite absent from shared provider-conformance E2E** (`PROV-01/03`, `BATCH-01..03`). `cache/cache_e2e_test.go` covers mem/redis/valkey/memcache/postgres, not sqlite. Equivalent coverage exists in-package; the harness itself is not run by CI.

**W4 — stale benchmark doc comment** (`QUAL-04`). `bench_test.go:449-451` still claims mem-only.

**W5 — documented `WithName` path has no permanent guard** (`STOR-01`, `QUAL-03`). Works by probe; nothing pins it.

**Also carried:** 9 open code-review findings from Phase 17 (intentionally deferred), 7 open audit artifacts, 2 drifted verification fingerprints.

*Out-of-scope observation:* `cache/doc.go:56` documents `ErrCanceled`, which does not exist anywhere in the codebase (predates Phase 17).
