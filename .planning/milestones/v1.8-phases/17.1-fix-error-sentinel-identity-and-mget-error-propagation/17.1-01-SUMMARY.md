# Phase 17.1 Plan 01: Fix error sentinel identity and MGet error propagation Summary

**A closed `cache/sqlite` handle now yields one `cache/sqlite:` prefix and matches both `sqlite.ErrClosed` and `cache.ErrClosed`; `MGet` is loud at `Error` and documented as the deliberate exception in both twin doc sites, and the cache package documents only sentinels that exist.**

## Accomplishments

- **W1 closed.** `sqlite.ErrClosed` is now `fmt.Errorf("cache/sqlite: %w", cache.ErrClosed)`, so `errors.Is` succeeds for both sentinels while `ErrInvalidPath` stays a plain `errors.New` (D-01/D-03). `check()` stopped re-wrapping: it returns `ErrClosed` and `ErrInvalidPath`-derived `initErr` values as-is and wraps only bare errors, so every deferred-open error leaves the package with exactly one prefix (D-04).
- **The defect is now unreachable by regression.** `TestClosedErrorPrefix` and `TestOptimizableClosed` assert the exact message `cache/sqlite: cache: cache is closed` and `strings.Count(..., "cache/sqlite") == 1`; all seven closed-path operations assert both `errors.Is` targets (5 in `sqlite_test.go`, 2 in `batch_internal_test.go`); the new `TestDeferredErrorPrefix` covers the validation branch and the bare `ENOTDIR` branch (still unwrapping to `*fs.PathError`).
- **W2 closed without an API change.** `MGetFunc`'s deferred-open log moved `Warn` → `Error` with the message and `"error", err` attribute byte-identical; the empty-map return is untouched (D-07/D-09). Both twin doc sites now carry `MGet is the exception` plus the frozen-signature reason, and neither still claims every database-needing operation returns the deferred error (D-08).
- **D-02/D-06 closed.** The phantom `ErrCanceled` declaration is gone from `cache/doc.go` (block re-aligned to `ErrClosed`), replaced by the machine-checkable sentence `Sentinel support is currently per-provider: cache/sqlite wraps …`; `cache/errors.go`'s `ErrClosed` comment names `cache/sqlite` as today's only wrapping provider, with the values untouched.

## Decisions Made

- **`check()` discrimination by identity, not text** (D-04, the plan's explicit discretion point): `errors.Is(c.initErr, ErrInvalidPath)` decides "already prefixed". This matches the repo's `errors.Is`-first habits and survives future message changes; the stringly `strings.HasPrefix` alternative was rejected.
- **`ErrClosed` needs no branch at all** — it is pre-prefixed by construction and returned directly, which is the whole of the closed-path fix.
- **`MGet is the exception` kept on one physical line** in both twin doc sites so the doc claim stays greppable/CI-checkable; the surrounding prose still wraps near the file's ~78-column width.
- **Doc wording avoids the retired phrases entirely** (`are returned by the first operation that needs the database`, `… returns them wrapped`) rather than negating them, so the plan's absence gates pass for the right reason.
