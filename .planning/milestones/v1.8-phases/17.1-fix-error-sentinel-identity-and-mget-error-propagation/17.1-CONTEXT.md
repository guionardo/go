# Phase 17.1: Fix error sentinel identity and MGet error propagation - Context

**Gathered:** 2026-10-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the two contract bugs the v1.8 milestone audit surfaced, plus the three adjacent debt items it logged and the user elected to absorb:

- **W1** — `sqlite.ErrClosed` duplicates the provider prefix (`cache/sqlite: cache/sqlite: cache is closed`) and `errors.Is(err, cache.ErrClosed)` is false for sqlite, while `cache.ErrClosed` is advertised as *the* closed sentinel.
- **W2** — `MGet` logs and returns an empty map when the deferred open error is set, while every other operation returns the error; `doc.go`'s "returned by the first operation that needs the database" is therefore false for `MGet`.
- **W3** — `cache/sqlite` is absent from the repo's shared provider-conformance E2E (`cache/cache_e2e_test.go`).
- **W4** — `cache/bench_test.go`'s `BenchmarkBatch` doc comment still claims mem-only.
- **W5** — the documented headline path `New(WithName("app"))` has no permanent test.

Out of scope: repo-wide adoption of `cache.ErrClosed` by the other five providers; a custom Is-preserving error type; repo-wide prefix normalization; an error-returning `MGetErr` API; returning `nil` from `MGet`; any change to provider logic beyond error identity, logging and docs.

</domain>

<decisions>
## Implementation Decisions

### Sentinel Identity (W1)
- **D-01:** `sqlite.ErrClosed` is defined by **wrapping the cache-level sentinel**: `ErrClosed = fmt.Errorf("cache/sqlite: %w", cache.ErrClosed)`. `errors.Is` then succeeds for both `sqlite.ErrClosed` and `cache.ErrClosed`, existing callers keep working, and no new type is introduced. — **Reversibility:** costly — once consumers key on `cache.ErrClosed` and on the message shape, changing either breaks their error handling.
- **D-02:** Scope is **sqlite only**. The other five providers keep their current behaviour (none returns `cache.ErrClosed`); `cache/doc.go` gains a note that sentinel support is per-provider today. Repo-wide normalization and "sqlite now, others as a follow-up phase" were both considered and declined.
- **D-03:** `sqlite.ErrInvalidPath` stays a plain sentinel because it has no cache-level counterpart: `errors.New("cache/sqlite: invalid path")` — prefixed exactly once, in its own definition.

### Prefix Mechanics (W1)
- **D-04:** **`check()` stops re-wrapping.** It returns `ErrClosed` or the deferred `initErr` as-is, and wraps only errors that are not already provider-prefixed. Every error value is prefixed exactly once. `check()` is the single seam all operations pass through, so the fix lands in one place.
- **D-05:** The **house double-token message shape is accepted**: `cache/sqlite: cache: cache is closed`, consistent with the existing `cache/sqlite: cache: key not found` produced by `fmt.Errorf("cache/sqlite: %w", cache.ErrMiss)`. A custom Is-preserving type (cleaner message) and repo-wide prefix normalization were considered and declined.
- **D-06:** `cache/doc.go`'s phantom `ErrCanceled` line is **removed** — it documents a sentinel that exists nowhere in the codebase (predates v1.8).

### MGet Error Surface (W2)
- **D-07:** **No signature or API change.** `BatchCache.MGet(ctx, keys...) map[K]V` is frozen and stays frozen; `nil`-return and an additive `MGetErr` were both considered and declined.
- **D-08:** The overreaching sentence in `doc.go` / `New`'s comment is corrected to name **`MGet` explicitly as the exception**: it returns an empty map and logs rather than returning the deferred open error, because the frozen signature has no error channel.
- **D-09:** The deferred-open-error log in `MGetFunc` moves from **`Warn` to `Error`**, so a broken cache is loud in consumer logs. No other behaviour changes.

### Absorbed Debt (W3/W4/W5)
- **D-10:** **W4** — `cache/bench_test.go`'s `BenchmarkBatch` doc comment is corrected to describe what it now runs: mem plus the always-run sqlite `Memory`/`File` families.
- **D-11:** **W5** — a permanent test or Example drives the documented headline path end to end: `New(WithName(...))` → directory creation → `Set` → `Close` → reopen → `Get`. It must not write into the developer's real cache directory.
- **D-12:** **W3** — `cache/sqlite` is registered in `cache/cache_e2e_test.go`'s `providerCase` so the shared conformance suite covers it (GetOrSet dedup, delete idempotency, MGet/MSet/MDel, TTL expiry, `Close`). sqlite is local, so no Docker gate applies.

### the agent's Discretion
- How `check()` distinguishes a bare `initErr` from an already-prefixed one (`errors.Is` checks against the exported sentinels, a small `isPrefixed`/`wrapOnce` helper, or a sentinel-aware switch) — the contract is "exactly one prefix", not a specific mechanism.
- Whether the `Warn` → `Error` change also adds a hint to the log message.
- W5's form: a `*_test.go` test versus an `Example`, and the isolation mechanism for `os.UserCacheDir()` (`t.Setenv` on `XDG_CACHE_HOME`/`HOME` into `t.TempDir()` is the natural route).
- Whether to also run `cache/cache_e2e_test.go` in CI (it is not run today); registering sqlite there does not require adding a CI step.
- Test naming and placement for the sentinel assertions; whether to assert message strings, `errors.Is` behaviour, or both (both is expected, since the message shape is a decided contract).

</decisions>

## Existing Code Insights

### Reusable Assets
- `check()` in `cache/sqlite/sqlite.go` is the single seam every operation calls first — D-04 is a one-function fix.
- The `var (...)` sentinel block at `sqlite.go:44-50` and `cache/errors.go:38-44` are the only definitions to touch.
- `providerCase` in `cache/cache_e2e_test.go` is a table — W3 is one new row, and mem proves a local (non-Docker) case is supported.
- `ExampleNew_withPath` in `cache/sqlite/example_test.go` is the exact shape W5 should follow (temp dir, Close, reopen).

### Established Patterns
- Sentinels are package-level `var` blocks; errors wrap with `fmt.Errorf("cache/sqlite: %w", …)`; providers add their prefix exactly once at the boundary.
- Miss parity is the reference for the double-token message: `cache/sqlite: cache: key not found`.
- `New` never fails; the error is deferred to the first operation (`initErr`).
- Repo rule: `make coverage-quick` green before every commit; Conventional Commits; no empty commits.

### Integration Points
- `check()` — every `*Func` in `sqlite.go` and `batch.go`.
- `MGetFunc` — the only operation that consumes `check()`'s error without returning it.
- `cache/doc.go` — sentinel documentation consumed by all provider authors.
- `cache/cache_e2e_test.go` — shared conformance harness; W3 adds sqlite to it.

</code_context>

<specifics>
## Specific Ideas

- Expected message strings after the fix: `cache/sqlite: cache: cache is closed` (closed) and `cache/sqlite: invalid path` (path validation) — both prefixed exactly once.
- Expected `errors.Is` behaviour: `errors.Is(err, sqlite.ErrClosed)` **and** `errors.Is(err, cache.ErrClosed)` both true after `Close()`; `errors.Is(err, sqlite.ErrInvalidPath)` true for a `?`/`#` path.
- The existing test at `sqlite_test.go:694-703` asserts only `ErrorContains "cache/sqlite:"`, which is why the duplication survived — the new assertions must check the full message (or a count of the token) plus both `errors.Is` targets.
- W5 must not pollute `os.UserCacheDir()`; isolate it with `t.Setenv` into `t.TempDir()`.
- `MGetFunc`'s log stays a single line; only its level changes.

</specifics>

<deferred>
## Deferred Ideas

- **Repo-wide `cache.ErrClosed` adoption** — the other five providers (redis, valkey, memcache, postgres, mem) still return their own closed errors. Declined for this phase; belongs in its own phase or a milestone cleanup.
- **Custom Is-preserving error type** — would yield `cache/sqlite: cache is closed` with full `errors.Is` semantics. Declined in favour of the house double-token.
- **Repo-wide prefix normalization** — stripping `cache:` from the cache-level sentinels so every message is single-prefixed. Declined: touches five providers and consumer-visible strings.
- **`MGetErr(ctx, keys) (map[K]V, error)`** — additive error-returning API. Declined: new public surface inside a gap-closure phase.
- **Returning `nil` from `MGet` on deferred error** — declined: new contract, and readers writing into the map would panic.
