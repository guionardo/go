# Phase 17.1: Code Review Report

**Reviewed:** 2026-10-27T09:13:47Z
**Depth:** standard
**Files Reviewed:** 9
**Status:** issues_found

## Summary

Phase 17.1 is a narrow gap-closure wave: make `sqlite.ErrClosed` wrap `cache.ErrClosed`, stop
`check()` from double-prefixing already-prefixed deferred errors, pin that contract with exact
message/prefix-count tests, document MGet as the exception to "the first operation returns the
deferred error", and register sqlite in the shared E2E conformance matrix.

**The core behaviour is correct.** I traced every path that can reach `check()`:

| `initErr` source | carries `cache/sqlite: ` already? | `check()` action | final message |
|---|---|---|---|
| `resolveLocation` path `?`/`#` (`dsn.go:49`) | yes (sentinel text) + `errors.Is` ErrInvalidPath | returned as-is | one prefix ✅ |
| `resolveLocation` invalid name (`dsn.go:55`) | yes + identity | returned as-is | one prefix ✅ |
| `resolveLocation` `os.UserCacheDir` failure (`dsn.go:60`) | no, no identity | wrapped once | one prefix ✅ |
| `MkdirAll` / `sql.Open` / `retryBusy` / `bootstrap` | no | wrapped once | one prefix ✅ |
| closed cache | n/a | returns `ErrClosed` (prefixed at definition) | one prefix ✅ |

Every call site (`GetFunc`, `SetFunc`, `DeleteFunc`, `MSetFunc`, `MDelFunc`, `checkpoint`,
`vacuum`) returns the `check()` error verbatim, `SingleflightGetOrSet.Do` does not re-wrap, and
`batchCache` only delegates — so no double-prefix path survives. `errors.Is` now resolves to both
`sqlite.ErrClosed` and `cache.ErrClosed`, and to `sqlite.ErrInvalidPath` through the deferred path.

I also verified the tests are not vacuous, rather than trusting green output:

- `go test ./cache/ ./cache/sqlite/`, `-race` on the new tests, and `go test -tags=e2e -run
  TestCacheE2E_SQLite ./cache/` all pass; `make coverage-quick` passes (sqlite 92.9%).
- `TestNewWithNameDurability` is genuinely sensitive to both properties it claims: I confirmed
  empirically that modernc's driver cannot create a missing parent directory (`Ping` →
  `unable to open database file (14)`), so removing `MkdirAll` would fail `first.Set`, and the
  `0700` assertion would fail a mode regression; the reopen read rules out a same-process cache.
- `TestDeferredErrorPrefix` is not satisfiable by a double-wrap (a second prefix breaks both
  `HasPrefix`/exact-string and the `Count == 1` bound), and `bare_open_error_wrapped_once` genuinely
  reaches the wrap branch (`MkdirAll` over the blocker file returns `*fs.PathError`/ENOTDIR).

No critical findings. The remaining defects are documentation that is now false about the code,
one observability regression in the changed log level, and test/verification gaps.

## Warnings

### WR-01: `cache/doc.go` sentinel note is false for `ErrMiss` — it tells consumers the opposite of the truth

**File:** `cache/doc.go:57-59`
**Issue:** The new note reads: "Sentinel support is currently per-provider: cache/sqlite wraps
cache.ErrMiss and cache.ErrClosed, while the other providers return their own errors. Consumers
branch with errors.Is, never with ==." Only the `ErrClosed` half is true. `cache.ErrMiss` is honoured
by **every** provider: `mem` returns it bare (`cache/mem/mem.go:49`), and redis (`redis.go:50`),
valkey (`valkey.go:57`), memcache (`memcache.go:66`), postgres (`postgres.go:80`) and sqlite
(`sqlite.go:216`) each wrap it with their own provider prefix. `ErrClosed` is the only sentinel with
single-provider support (no non-sqlite provider references it at all). As written, a consumer
reading the package godoc would conclude `errors.Is(err, cache.ErrMiss)` is unreliable outside
sqlite and fall back to `==`/string matching — exactly the anti-pattern the following sentence
forbids.
**Fix:** State the actual split:
```go
// cache.ErrMiss is honoured by every provider: the in-memory provider returns it
// bare and the remote providers wrap it with their own prefix. cache.ErrClosed is
// returned only by cache/sqlite; the other providers do not signal close yet.
// Consumers branch with errors.Is, never with ==.
```

### WR-02: The phantom-sentinel cleanup is incomplete — three public docs still advertise `ErrCanceled`/`DoChan`/`*cache.Panic`

**File:** `cache/doc.go:52-55` (fixed) vs `README.md:182`, `README.md:185`, `docs/ARCHITECTURE.md:60`, `docs/ARCHITECTURE.md:62`, `docs/ARCHITECTURE.md:83`, `CHANGELOG.md:12-15`
**Issue:** This phase removes the non-existent `ErrCanceled` from the package godoc, but the same
phantom API remains published elsewhere:
- `README.md:182` — `var ErrCanceled = errors.New("cache: canceled")`, and `:185` — "A canceled
  `DoChan` waiter receives `ErrCanceled`".
- `docs/ARCHITECTURE.md:62` — "`DoChan` adds per-caller cancellation … wrapping both
  `cache.ErrCanceled` and its own `ctx.Err()`"; `:83` — "provides cancel-aware `DoChan`";
  `:60` — `*cache.Panic`.
- `CHANGELOG.md:12-15` — records `DoChan`, `*cache.Panic` and `ErrCanceled` as shipped in v1.6.

`grep -rn "DoChan\|ErrCanceled" --include=*.go` returns **zero** hits, and the panic type is
`cache.PanicError` (`cache/errors.go:15`), not `cache.Panic`. So the phase fixed the least visible
of four places and the user-facing docs still document symbols that do not exist; anyone following
them gets a compile error. Fixing only `doc.go` while README keeps the lie is a partial fix, not a
closed gap.
**Fix:** Delete the `ErrCanceled`/`DoChan`/`*cache.Panic` claims from `README.md` and
`docs/ARCHITECTURE.md` (replace `Panic` → `PanicError`), and correct the v1.6 `CHANGELOG` entry:
`Do` only, panic recovery → `*cache.PanicError`, no `ErrCanceled`.

### WR-03: `MGet` now logs an expected lifecycle state (`ErrClosed`) at Error, louder than a real chunk failure

**File:** `cache/sqlite/batch.go:79-83`
**Issue:** The `check()` branch logs **every** deferred/closed condition at `Error`, because the
change targeted deferred open errors only. `check()` also returns `ErrClosed` — a normal
end-of-lifecycle state (shutdown ordering, a `Close` in `t.Cleanup`, a raced close). Consequences:
(a) any `MGet` after `Close` now emits an Error line on every call, which is alert-worthy noise in
production; (b) severity is inverted inside the same function — a genuinely failed chunk (`:114`),
row scan (`:125`) or iteration (`:141`) logs at `Warn`, while the benign "already closed" condition
logs at `Error`; (c) `cache/sqlite/doc.go:62-63` and `batch.go:74-75` describe the Error-level path as
"a deferred open error", which no longer matches the code's broader trigger.
**Fix:** Split the condition so severity tracks cause, and keep the docs literal:
```go
if err := c.check(); err != nil {
	if errors.Is(err, ErrClosed) {
		logger().Warn("cache/sqlite: batch get on closed cache", "error", err)
	} else {
		logger().Error("cache/sqlite: batch get skipped", "error", err)
	}

	return result
}
```

### WR-04: The new conformance registration is never executed by CI, so it adds no regression protection

**File:** `cache/cache_e2e_test.go:244-253` (new `TestCacheE2E_SQLite`)
**Issue:** The test itself is fine — it has no `testing.Short` or Docker gate and I ran it green
locally. But it is inside `//go:build e2e`, and the only e2e step in CI is
`.github/workflows/go.yml:70-71`:
`go test -tags=e2e -run 'TestTwoProcess' ./cache/sqlite/`. Nothing runs `TestCacheE2E*` in CI. The
Makefile target that does (`Makefile:90-93`, `test-e2e`) runs the whole matrix, including the
Docker-backed cases, so it is only usable where Docker is available, and
`coverage`/`coverage-quick` (`Makefile:110-121`) compile the `e2e` tag out entirely. Net effect: the
registration is inert unless a human remembers a separate command — the classic "conformance matrix
entry that nobody runs" that reads as coverage in a summary but protects nothing.
**Fix:** Add a containerless CI step (cheap, no Docker, ~3 s):
```yaml
- name: Cache E2E (no Docker)
  run: go test -tags=e2e -run 'TestCacheE2E_Mem|TestCacheE2E_SQLite' ./cache/ -v -count=1 -timeout=120s
```

### WR-05: The "exactly one prefix" invariant is enforced for exactly one sentinel, and the third deferred-error shape has no test

**File:** `cache/sqlite/sqlite.go:187-201` (with `cache/sqlite/dsn.go:58-61`)
**Issue:** `check()` recognises "already prefixed" solely via `errors.Is(c.initErr, ErrInvalidPath)`.
That is correct for today's three sources, but the invariant the phase is pinning ("every error leaves
`check()` with exactly one prefix") is now a convention spread across three files, not a property the
code enforces: `resolveLocation`'s `os.UserCacheDir` failure (`dsn.go:60`) is deliberately **bare**, so
it depends on `check()` wrapping it; if anyone later "tidies" that return to
`fmt.Errorf("cache/sqlite: resolve user cache dir: %w", err)` — the obvious thing to write, and what
the other sentinels already do — `check()` will double-prefix it and no test will notice, because the
third shape is not covered (only `ErrInvalidPath` and `MkdirAll`/ENOTDIR are). This is a
maintainability defect in the exact contract the phase set out to guarantee, not a live bug.
**Fix:** Pin the third shape with an in-package test over all three `initErr` sources, which needs no
new seam because `check()` returns before touching `db`:
```go
func TestCheckErrorPrefixMatrix(t *testing.T) {
	t.Parallel()

	_, _, dirErr := resolveLocation(&Config{Name: "app"}, func() (string, error) {
		return "", errors.New("no home")
	})

	_, _, pathErr := resolveLocation(&Config{Path: "bad?path"}, nil)

	for name, initErr := range map[string]error{"cache_dir": dirErr, "invalid_path": pathErr} {
		t.Run(name, func(t *testing.T) {
			t.Parallel()

			c := &sqliteCache[string, string]{initErr: initErr}

			_, err := c.GetFunc(t.Context(), "k")
			require.Equal(t, 1, strings.Count(err.Error(), "cache/sqlite: "))
		})
	}
}
```
Longer term, give every deferred error source the same treatment as `ErrClosed`/`ErrInvalidPath`
(prefixed where it is created) and have `check()` return `c.initErr` verbatim, so the invariant is
structural instead of identity-sniffed.

## Info

### IN-01: Prefix-count assertions match `"cache/sqlite"` instead of the delimiter `"cache/sqlite: "`

**File:** `cache/sqlite/sqlite_test.go:721`, `:741`, `:770`, `:864`
**Issue:** `strings.Count(err.Error(), "cache/sqlite")` counts the bare substring. In
`bare_open_error_wrapped_once` the asserted error is a wrapped `*fs.PathError` whose text embeds a
filesystem path — if `TMPDIR` were ever set to something containing `cache/sqlite` (e.g. a
per-package CI scratch dir), the count would be inflated and the test would fail for an unrelated
reason. Cheap hardening; today's temp dirs do not contain the token.
**Fix:** Count the delimiter, which is what the contract is about:
`strings.Count(err.Error(), "cache/sqlite: ")`.

### IN-02: `TestNewWithNameDurability` leaks the first handle on any early assertion failure

**File:** `cache/sqlite/sqlite_test.go:913-923`
**Issue:** `first := sqlite.New(...)` is closed only at `:916`. If `first.Set` (`:915`),
`require.FileExists` (`:918`) or the permission assertion (`:926`) fails, `require` calls `FailNow`
and the DB handle stays open; `t.TempDir` cleanup then fails too, masking the real cause with a
secondary teardown error (Windows is the worst case). `Close` is idempotent, so registering cleanup is
free.
**Fix:** Add `t.Cleanup(func() { _ = first.Close() })` right after `first := ...`, as the rest of the
file does for every provider.

### IN-03: Asymmetric closed/deferred assertions leave one regression path unpinned

**File:** `cache/sqlite/sqlite_test.go:866-870`, `cache/sqlite/sqlite_test.go:567-568`
**Issue:** In `TestOptimizableClosed`, `Checkpoint` pins the exact message **and** the prefix count,
but `Vacuum` only asserts `ErrorIs` + `ErrorContains` — even though both share `check()`, so a
regression that re-prefixes would be caught for one and missed for the other. Symmetrically,
`TestClosedOps` asserts both sentinels for `Set`/`Delete` but only `sqlite.ErrClosed` for `Get`
(`:567-568`), while `TestClosedErrorPrefix` covers `Get` fully — the difference is invisible to a
reader and invites the same drift next time.
**Fix:** Mirror the four assertions for `Vacuum`, and add
`require.ErrorIs(t, err, cache.ErrClosed)` to the `Get` case (or delete the redundant assertions from
`TestClosedOps` and point at `TestClosedErrorPrefix`).

### IN-04: The matrix registers only `sqlite_memory`, and the shared harness does not assert the sentinel identity this phase just fixed

**File:** `cache/cache_e2e_test.go:244-253`, `cache/cache_e2e_test.go:53-58`
**Issue:** Two coverage gaps in the registration: (a) only `WithMemory()` is registered, so the
durable/file-backed path the provider is documented for never enters the shared matrix; (b) the
harness's `get_miss` subtest asserts only `err != nil`, and `delete`/`mdel_*` likewise, so the new
case would still pass if `Get` returned a raw `sql.ErrNoRows` or an unwrapped provider error — i.e.
the matrix does not exercise `errors.Is(err, cache.ErrMiss)`, which is the identity half of this
phase's subject. All providers honour `cache.ErrMiss` today (see WR-01), so tightening the assertion
is safe for the whole matrix.
**Fix:** In `get_miss`, assert `errors.Is(err, cache.ErrMiss)`; add a `sqlite_file` case next to
`sqlite_memory` (`sqlite.WithPath(filepath.Join(t.TempDir(), "e2e.db"))`) so the WAL/durable path is
conformance-checked too.

### IN-05: `ErrClosed` comment implies other providers return an unwrapped closed error

**File:** `cache/errors.go:42-44`
**Issue:** "Only cache/sqlite wraps it today, so errors.Is(err, cache.ErrClosed) holds for that
provider and not yet for the others" reads as "the others return their own closed sentinel". They
return no closed indication at all: `mem.CloseFunc` empties the store so a later `Get` reports
`cache.ErrMiss` (`cache/mem/mem.go:49`), `redis.CloseFunc` just closes the client (subsequent ops
surface the driver error), `memcache.CloseFunc` returns nil and keeps serving. The distinction matters
because a consumer may reasonably expect `ErrClosed` after `Close` from a "sentinel-complete"
provider and get a miss instead — silent cache-miss behaviour, not an error.
**Fix:** Make the negative explicit: "cache/sqlite is the only provider that signals close
(errors.Is(err, cache.ErrClosed) holds there); the other providers do not return a closed error — mem
reports ErrMiss after Close, and the network providers surface the driver/connection error."
