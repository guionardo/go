<feature>
  <name>SingleflightGetOrSet.Do — blocking dedup helper with panic recovery and clobber guard</name>
  <files>cache/singleflight.go, cache/errors.go, cache/singleflight_test.go, cache/example_test.go</files>
  <behavior>
    Testable contract (RED phase writes these; ALL MUST FAIL to compile or run before implementation exists):

    - Case 1 — setter runs once for N concurrent misses: 50 goroutines call Do on the same key against a mutex-guarded stub store; the setter (3ms sleep + atomic counter) runs exactly once; all 50 results equal "computed"; a second-phase Do returns the cached value WITHOUT re-running the setter (setter panics if invoked).
    - Case 2 — panicking setter: setter panics with a string; every waiter's error is a *cache.Panic (require.ErrorAs) whose Error() contains the panic value; no panic escapes the Do call; when the panic value is a sentinel error, errors.Is(err, sentinel) holds through Panic.Unwrap().
    - Case 3 — zero-value setter: setter returns the zero value ("") with nil error; it is stored and returned; dedup waiters receive the identical value.
    - Case 4 — clobber guard (SF-08): the get closure blocks on its first (fast-path) invocation until a direct Set("fresh") lands; after release, the double-check Get inside the fn hits "fresh" → Do returns "fresh", the setter NEVER runs, and the store still holds "fresh".
    - Case 5 — TTL passthrough (D-18/D-19): the set closure records the ttl it receives; a leader with ttl=5s → recorded ttl == 5s exactly; with two concurrent callers passing different TTLs (leader deterministically first via a blocked setter), the recorded ttl equals the LEADER's ttl.
    - Case 6 — leader cancel (D-05/D-11): the setter blocks on <-ctx.Done() then returns ctx.Err(); canceling the leader's ctx → Do returns the raw context.Canceled error: errors.Is(err, context.Canceled) holds AND the raw error equals ctx.Err() (assert.Equal on the raw error, no reference to cache.ErrCanceled). cache.ErrCanceled is a 05-02-owned symbol (defined in plan 05-02's GREEN); 05-01 tests must NOT reference it — it does not exist in 05-01's compile scope (referencing it fails 05-01's build with undefined, and defining it early would redeclare in 05-02). The leader-path assertion is raw-error equality only.
  </behavior>

    - `func (s *SingleflightGetOrSet[K, V]) Do(ctx context.Context, key K, get func(context.Context, K) (V, error), set func(context.Context, K, V, ...time.Duration) error, setter func(context.Context) (V, error), ttl ...time.Duration) (V, error)` (D-04, D-06, D-12: single explicit ctx; both get and set take ctx).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| setter → wrapper | A panic raised inside the setter crosses into the singleflight fn; x/sync would replay it to every waiter (panicError) — the wrapper is the recovery boundary (D-16) |
| waiter → leader | Waiters' contexts are untrusted; they must never cancel or reach the shared computation (D-04) |
| get/set closures → shared store | Concurrent Get/Set on the provider store crosses goroutine boundaries; the store must be race-free |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | DoS | callSetter / Do | high | mitigate | Recover inside the singleflight fn (D-16) and return *cache.Panic to every waiter (D-17) — a panic can never escape to any caller goroutine; verify with TestSingleflightGetOrSet_PanicRecovery + require.ErrorAs |
| T-05-02 | Tampering | Do fn body | high | mitigate | Double-check Get inside the fn (SF-08) so a stale in-flight computation cannot clobber a concurrent direct Set; verify with TestSingleflightGetOrSet_ClobberGuard |
| T-05-03 | DoS | Do fast-path | medium | mitigate | Fast-path Get stays OUTSIDE the group (SF-02) to avoid singleflight lock contention on cache hits; verify with the second-phase cached-read assertion |
| T-05-04 | Information Disclosure | Panic.Error() | low | accept | Stack traces surface in error text — same behavior as x/sync panicError (D-17); errors are caller-visible by design; no secret material expected in recovered values |
| T-05-05 | DoS | Do (blocking) | medium | accept | Do is context-blind for waiters (D-06) — a long setter holds waiters until completion; documented on godoc; the DoChan variant (plan 05-02) is the HTTP-path choice (spike 008) |
| T-05-SC | Tampering | module deps | low | accept | No new packages installed this phase; golang.org/x/sync v0.22.0 already pinned in go.mod (D-15) — no package-legitimacy checkpoint required |
</threat_model>
