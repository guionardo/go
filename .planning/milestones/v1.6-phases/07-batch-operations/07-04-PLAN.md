    - Create batch, resolve TTL once
    - Iterate items: `json.Marshal(value)` — hard failure on error. Queue INSERT per key
    - Execute SendBatch, defer Close

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-09 | Tampering | SQL injection via table name or key | low | accept | All batch queries use pgx.Identifier{c.tableName}.Sanitize() for table names and parameterized $1 placeholders for key values — same pattern as existing GetFunc/SetFunc/DeleteFunc. No new injection surface. |
| T-07-10 | Denial of Service | SendBatch with large batch | low | accept | pgx SendBatch queues all queries in one round trip. Memory usage scales with batch size. Same pool config as single-key ops. |
| T-07-11 | Repudiation | Batch result consumption incomplete | low | accept | All batch methods consume ALL results (iterate items/keys count matching queue count). defer br.Close() ensures cleanup. |
| T-07-12 | Tampering | MGet missing key as cache hit | low | accept | pgx.ErrNoRows is checked per individual query result — missing keys are correctly skipped. |
</threat_model>
